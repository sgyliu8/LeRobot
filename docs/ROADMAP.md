各阶段按依赖推进，不按日历作不可靠工期承诺。阻塞硬件时继续不依赖它的软件切片。

## M0 — 不把新项目提交到父仓库

实施：读关键合同；核对目标目录自己的 Git；检查父 tracked/ignore；按 bootstrap 处理父 local exclude；复核远端；空远端才创建文档 baseline main，再创建 `codex/bootstrap-so101-lab`。
不把用户已经放入的 pack 删除后强行 clone。不在父根运行 Git 写操作。
验收：T-GIT-01/02/03、离线 pack validator 通过；子 remote 正确；父受控文件和 HEAD 不变；baseline commit 与 feature branch 有记录。
学习目标：分清知识平台、实验工程、上游源码三个身份。
退出：目录或远端存在冲突历史时暂停相关 Git 写入；不停止可继续的源码分析。

## M1 — 官方工作台真正能在本机启动

实施：按候选 SHA 建独立 Python 3.12 环境；解析并保存真实 uv.lock；核对 LeRobot v0.6.0 commit；复用 shipped frontend；核查缓存路径和初次访问是否触发设备打开。
建立最少的 start/status/logs/stop 入口，只管理已证明归属本项目的进程。先做软件停止，不测试运动中的强杀。
复查 API 写入来源、跨模式互斥、零值 telemetry 与 motion-limit 传递；缺口用无硬件测试复现后补小 patch，不更换框架。
验收：包导入、正确可执行文件、无设备页面、关闭/重开、已有端口冲突、未授权起动路径、重复请求测试；软件有真实截图与日志。
不能把 mock 数据、录制 test_mode 或 UI 存在作为机械臂在线证明。
学习目标：理解 LeLab/LeRobot/依赖锁/本地服务的层级。
退出：软件错误通过固定版本源码和可复现日志定位；不自动装所有 policy extras 或重装系统。

## M2 — 主机与设备身份，而不是“看见 COM 就连接”

实施：复查 Codex 执行主机与实物所在电脑；Windows PnP、设备管理器、数据线、端口/hub及驱动状态；必要时由用户一次只拔插一件设备完成差分映射。
普通 COM1 不用作机械臂。若没有 USB serial 设备，先检查设备在哪台主机和数据连接，不以反复 lerobot-calibrate 排障。
驱动安装只采用已核实控制板/芯片对应官方来源，系统级安装由用户批准。没有证据不猜 CH340/CP210x 型号。
验收：两只独立控制板的 OS 身份、主从角色、重新插拔后的再识别策略；或具体可验证的阻塞原因。
学习目标：USB 枚举、串口设备、舵机总线与 actuator power 的区别。

## M3 — 双视角相机先独立跑稳

实施：一次确认一台相机；固定 `wrist`/`front`，记录 OS 身份和实际 backend。Windows 固定候选采用 DSHOW 路径，但必须验证 preview→record 映射一致。
先试 640×480、15 fps；实测稳定再评估 30 fps。配置 fps、到帧率、record loop fps 是不同字段。
建议 60 s 双路预览/相机-only采样；记录有效帧、时间单调性、到帧间隔分位数、CPU/RAM/磁盘。静止场景同像素不等于丢帧。
建议吞吐验收目标为每路实际有效速率 ≥目标的 90%，且有效窗口无无法解码帧；这是项目初始工程门槛，不是同步精度或机械安全保证。
测试后释放句柄，再启动正式 recorder；不能让 Windows Camera、浏览器 getUserMedia 和 backend 各自占同一设备。
验收：T-CAM-01..04；身份和显示角色吻合；缺一路时禁止启动“双视角合格”采集。
学习目标：两相机视角、捕获后端、软时间关联与硬同步的区别。

## M4 — 现场硬件确认与第一次有限运动

入口：明确套装/电机与电源标签、机械固定/夹点、线缆余量、起始姿态、操作者在场和独立停机方式；所有未知集中问一次。
首先查已有 motor setup/calibration，不盲目重写 ID/波特率/固件。`connect()` 的副作用纳入批准。
分开完成 leader 与 follower 校准，保存本项目范围备份。校准中的人工支撑、失能、满范围动作按实际装配处理，不强推机械止挡。
设置并确认启动姿态和允许的有限目标变化；`max_relative_target` 是步目标偏差约束，不是速度/碰撞/力约束。
使用所有者预先同意的小范围试动和简单轻质物体；必要时先不放物体。先证明能正确跟随和停止，再做抓放。
验收：端口/方向/状态单位/首动无意外跳变/停止状态/断开策略有现场结果。一次正常动作不证明长期安全。
失败：异常力、过热、抖动、撞限位、未知指令或状态陈旧即停止；不自动重复动作，重新评估后另行恢复。
学习目标：电机设置、校准、位置控制、反馈和安全边界。

## M5 — 第一份可用数据，而不是先录几百次

定义一个简单抓放任务与成功条件，固定相机安装和任务文字。用 LeRobotDataset 记录三个 20–30 s 左右的短回合，时长以完整任务为准，不强行截断。
先一回合→查看→再另外两回合；修复问题后重新验证，不扩大错误数据规模。
审计实际 action 来源、关节顺序、degree/normalised gripper、两路 MP4 与 metadata、reset 排除、提前结束/中断。
结束并释放硬件后，用本地数据浏览功能逐回合确认。Browse 测试必须在没有执行器访问的条件下完成。
故障注入先用合成 fixture 模拟丢失视频/未 finalize；不要在运动中拔线制造试验。
验收：T-DATA-01..05；三回合完整、两视角可解码、内容/索引相符、没有自动上传；v0.1 可作为实验台候选。
学习目标：observation/action/episode/task/metadata，以及记录与物理执行之间的差别。

## M6 — 一个可解释的 ACT 基线

扩大到初始建议 30–50 条质量检查过的任务示范，不把数量当性能保证。按 episode/session 分割训练与验证，最终评估条件单独保留。
GPU 方案未确认前先小样本 load/batch/前向 smoke；不在 16 GB CPU 机器上盲跑长训练。
训练前记录预算、设备、policy配置、观测键、图像处理、归一化、action horizon、数据修订和种子。日志、检查点存本地，wandb/Hub/云默认不启用。
验收：数据读取与 batch 正确、loss/输出有限、checkpoint 可加载、离线推理形状/单位/速率测得；不是模型会抓取的证明。
学习目标：行为克隆、ACT 动作块、分布偏移、loss 与任务成功的区别。

## M7 — 真机评价而不是挑成功视频

冻结任务、初始状态范围、N 次评估和时间上限；建议首批 10–20 次作为小样本工程评价，不作工业可靠性推断。
所有已开始尝试进入分母，分别记录成功、失败、人工干预、异常中止、超时；不要把中止偷偷删掉。
预运行审计模型→processor→动作→设备合同，测量实际 observation-to-target latency。CPU 不满足循环要求则不硬上机。
新 inference 模式需新的现场确认；只执行有限批次，不自主扩展任务。
验收：完整评估表、失败例、版本身份、边界结论；超过阈值的风险事件单独处理。
学习目标：闭环误差、恢复、latency、数据覆盖和公平对照。

## M8 — 把使用变成研究

优先比较 wrist-only、front-only、two-view 三种观察配置：保持训练预算/分区/任务尽可能一致，报告可比条件和混杂。
导出本地 experiment summary，用现有 PhysicalAI 入口关联 ACT、感知、控制与数据章节。
ROS 2/FK/IK/手眼/仿真在新问题需要时进入下一 ADR；不是 v0.1 阻塞项。
验收：摘要与原始运行相符；公共门户不含敏感路径或家庭视频；不宣称未做过的仿真或复现。
