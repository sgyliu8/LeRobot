# Five-role / Three-round Review Protocol

## Execution truth

本包评审由同一个助手按五专业角色进行三轮交叉审查。不是五个独立模型实例、不是外部专家会审，也不是机器人功能安全认证。
下述内容是可公开的发现、质疑、依据与修订决定，不是虚构会议逐字稿。
未来Codex有独立subagents时可以真的分派，但需记录实际运行方式，不能回写本次为独立评审。

## Roles

R1 — 机器人/机电与现场安全：连接副作用、电源、校准、运动、停止。
R2 — 软件架构/上游集成：复用边界、版本、包名、缓存、状态所有权。
R3 — 数据/学习与实验：相机、动作语义、Dataset、训练/评估证据。
R4 — Windows/Computer Use/UX：真实设备、窗口/权限、role mapping、错误状态。
R5 — 交付/安全/版本控制：嵌套Git、隐私、CI、来源、可复现与审计。

## Rounds

Round 1：审问题定义/范围，拒绝不必要的重建和未说明的权限扩大。
Round 2：用固定源码、本地枚举和负例挑战接口/数据/停止等细节；修改文件合同。
Round 3：沿用户“解压→Codex→启动→相机→现场→回合→浏览”路径检查文档间一致性；检查包文件/链接/示例和实际验证范围。

## Issue format and closure

每个问题记录ID、角色、严重度、依据、其他角色的挑战、决定、修改落点、验收用例和状态。
严重度 Critical/Major/Minor 指计划风险，不与测试层P0–P5混用。
闭合分两类：DOC_CLOSED表示计划/合同已修正；RUNTIME_PENDING表示风险须在未来gate实际验证。
不以“没有遗留文档阻塞”暗示实物安全或代码无缺陷。外部事实/运行结果不能通过角色投票变成真的。

## Acceptance

没有遗漏关键执行边界、相互矛盾的单一权威、伪造设备/版本/测试状态；初次启动任务能实际执行且不过度防御。
包静态验证和unit测试独立报告，见PACK_VALIDATION；真实软件与硬件结果不从本review继承。
