# Requirements — 先用现有系统，再补真实缺口

**Authority:** product contract. **Owner:** Yang Liu. **Version:** 1.0.0.

## 1. 经过补全的问题定义

原始愿望是“让 Codex 把主从双臂和双摄像头组合到自己的平台”。可交付的问题应改写为：
在明确的 Windows 主机、独立子仓库与固定依赖上，复用 LeLab/LeRobot；让操作者能理解设备状态并安全地完成受监督的校准/遥操作、可靠的双视角数据记录、本地检查、ACT 训练与有分母的真机评估。每一阶段必须有可观察结果，并可追溯到软件版本、设备配置、数据与模型。

“所有需要的东西”不是一次安装所有机器人技术。它指当前任务链路不缺关键环节，同时后续扩展有接口而不强迫现在实现。

## 2. 用户与设备

单用户、本地优先、Windows 原生。中文学习说明，保留上游英文 UI；不为首版强制翻译整个 LeLab。
一个 leader 提供示范，一个 follower 执行任务。不是两执行臂协同。
两个视觉角色：`wrist`（手上眼）与 `front`（固定场景眼）。设备型号、驱动、端口、分辨率、实际帧率和相机外参仍需实测。
当前主机无已枚举到的 NVIDIA GPU，不把 GPU 作为遥操作/采集的前置条件；正式训练与推理预算单独验证。

## 4. 三个可交付版本

**v0.1 / 可用实验台（M0–M5）：** 独立 repo、可重建环境、官方 GUI、已确认设备/校准、受监督主从跟随、双摄像头三个短回合、本地可浏览；没有模型也可验收。

**v0.2 / 学习闭环（M6–M7）：** 有任务定义的数据集、ACT 基线、离线输入/输出验证、经现场批准的评估，失败不隐去。

**v0.3 / 研究关联（M8）：** 将实验摘要、数据/模型身份及失败分析连接到现有 PhysicalAI；不把公共研究网站升级为远程控制面。

## 5. 非目标

首版不开发全新 React/PySide 工作台，不建新驱动、格式或训练器；不先接 ROS 2/MoveIt/Isaac；不训练大 VLA；不做自动固件刷写；不提供无人值守机械运动；不做工业精度/安全保证；不承诺双摄像头硬同步或公制三维。
首版不要求完整手眼标定才准采集 RGB 模仿学习数据。若任务变成公制定位，几何标定再成为相应阶段的必需条件。

## 6. 非功能要求

可重复：锁定运行环境和上游身份，不靠一个不可重建的 site-packages 修改。
可理解：区分未发现、已枚举、已打开、已标定、可运行、运行中、故障与未知状态。
可恢复：保留有效回合，取消操作不抹去证据；软件重启不自动恢复机械动作。
适度性能：记录实际双路吞吐、CPU/RAM/磁盘和延迟分布，不以 UI 刷新率充当控制频率。
可维护：一事实一权威文件；无真实缺口不新增服务；测试针对风险，不追求文档数量。
可迁移：绝对路径仅出现在项目身份/本机配置；运行代码从自身根目录定位资源。

## 7. 变更规则与未知事项

新增功能先问“上游是否已有”。只有重复且重要的操作缺口才允许新增功能。
通用软件/接口问题查官方文档和固定源码；实物电源、装配、主人是否在现场不能靠网络推断。
硬件未知项集中记录在 HANDOFF 和本地配置，阻止相关动作，不无限阻止不相关软件工作。
任何需求变更同步更新相应 roadmap、测试与 ADR；不得以“完成度更高”为由自动扩大权限。
