# UI Specification — 复用官方界面，补可理解性，不重造外壳

## 1. 设计目标与证据边界

当前设计对象是 **LeLab 官方 UI 的使用、验证和最小适配**，不是新应用视觉探索。
本包未运行 LeLab，也未提供冒充运行截图的效果图。以下线框是信息/交互需求示意，不宣称对应现有 route 或 pixel layout。
M1 先截图并建立实际页面 inventory；凡上游已有的界面直接使用。只有关键需求无法表达且有证据时才增加字段或小型面板。

## 2. 用户旅程

```text
启动工作台
  → 了解当前主机/版本/未连接状态
  → 识别 Leader / Follower 和 Wrist / Front
  → 相机独立预览
  → 现场确认与校准
  → 有限遥操作
  → 录制任务回合
  → 停止并浏览本地数据
  → 训练（后期）
  → 有限真机评估（后期）
```

首屏不要把用户推向注册、Hub 上传、云 GPU 或复杂 policy 选择。
上游可能存在这些入口，不代表应删除所有入口重构 UI；用默认配置、明确说明和必要的权限护栏控制误操作。

## 3. 工作台全局信息

```text
PhysicalAI SO101 Lab                   本地模式 | LeLab/LeRobot版本
设备操作：闲置 / 相机预览 / 记录中 / 故障 / 状态未知
----------------------------------------------------------------
Leader:  尚未识别       Follower: 尚未识别
Wrist:   尚未映射       Front:    尚未映射
现场权限: 未建立        上传: 默认关闭
----------------------------------------------------------------
下一步：识别当前主机与 USB 设备
[打开官方设备配置]   [查看本地诊断]   [操作说明]
```

不是强制新增全局仪表板；上游页面能表达的信息就用原位置。
绿色必须只表示特定已验证状态，例如“相机有新帧”；不得泛称“系统安全”。
端口已枚举、串口已打开、关节可读、已标定与可移动分别显示；一个 Connected 标签不能替代整个层级。
本项目需新增文字时中文优先、技术标识保持规范；不强制改写上游所有英文文案。

## 4. 设备配置和双摄像头页面

两臂角色固定并并排可比较，不根据数组顺序推断。
展示可读设备名、端口、识别依据、校准文件名/日期及最后检查时间；详细 USB instance ID 放在本地详情，不进入公开报告。
未知端口不是可执行默认值，禁用继续进入电机动作的路径并说明缺什么。
校准按钮必须说明可能写入电机和需要人工移动，不得与“检测连接”混成一个按钮。

双相机面板的信息结构：

```text
WRIST — 夹爪局部                     FRONT — 固定场景
[真实画面 / 明确缺失提示]             [真实画面 / 明确缺失提示]
设备名 · backend · 请求分辨率         设备名 · backend · 实际分辨率
请求FPS / 实测到帧率 / 最后帧时间     请求FPS / 实测到帧率 / 最后帧时间
[重新确认角色]                       [重新确认角色]
```

选择相机后，用逐个遮挡或操作者确认识别视角；不要用 AI 猜物理安装角色。
preview→record 使用同一身份/后端解析结果；浏览器 deviceId、DirectShow index、OS instance ID 不是同一个命名空间。
一台设备不能同时被选作 wrist 和 front；同名无序列号设备通过插拔/物理端口/人工确认消歧。
ROI、目标检测、深度图和标定叠加均为后续扩展，首版不做占位空面板。

## 5. 遥操作页面

主要显示模式、关节读数/单位、数据新鲜度和停止入口；3D 视图沿用 upstream。
3D 模型标明“运动示意”，不标“已校验数字孪生”。夹爪动画映射必须和量度字段分离。
启动前给出明确的作用范围：将使用哪两臂、哪组校准、是否写入配置、当前目标限制。
关节显示采用统一顺序：shoulder_pan、shoulder_lift、elbow_flex、wrist_flex、wrist_roll、gripper。
前五个是否为 degree 以实际配置为准；gripper 的 0–100 是归一化位置，不显示 ° 或 mm。
失去 telemetry 显示“数据陈旧/未知”，不填零或冻结为绿色在线。

Stop 应始终易找，但必须写清“停止任务/停止发送”与实际失能后果；不把普通 Web 按钮标成经过认证的 Emergency Stop。
首次运动时操作者不依赖 Computer Use 正在占用的鼠标或空格键来停止。

## 6. 采集页面

顶部显示任务描述、dataset_id、本地路径的简化名称和本地模式。
主区域显示两相机、回合计数、状态（准备/记录/重置/完成）、剩余时长和真实保存数量。
明确区分：结束当前回合、重录当前回合、结束会话、删除数据。删除是另外的确认，不与重录自动绑定。
重置阶段不能静默混入任务帧；提前结束后的回合长度按 metadata 和实际 frame 解释。
保存成功应基于 finalize/索引/媒体结果，不只依据 UI toast 或线程被启动。
上传默认 false；private flag 不等于没有网络上传。
故障后给出已经保存的回合与待检查数据，不做“全部失败所以自动清空”。

## 7. 数据浏览页面

Browse 明确标注“只读检查，不驱动机器人”。Replay 明确标注“真机动作重放，需要现场确认”。
两路视频/帧与状态曲线按对应回合索引展示；不以共享 MP4 文件长度替代回合长度。
选择缩略图后必须显示正确 frame index；失败帧保持缺失，不造成后续索引整体错位。
边界前一帧/末帧/超范围测试能发现跨回合寻址错误。
本地数据浏览不强迫先上传到 Hub，不把“上传”作为 viewer 的唯一入口。

## 8. 训练与评估页面（M6+）

沿用现有训练任务 UI。显示真实 compute device、本地/云目标、数据身份、模型配置、检查点与日志。
未确认 GPU 或未支付授权时不自动发起 cloud job。
训练 loss、离线输出和真机成功率分开显示；训练完成不是学会任务。
评估摘要显示 numerator/denominator、人工干预、中止和任务范围，不能只显示精选成功视频。

## 9. 错误、无障碍与视觉原则

保持上游样式，少量项目说明与现有 typography/spacing 一致。设备角色和危险动作不只靠颜色区分。
优先桌面 1440×900 与常见笔记本 1366×768；缩小窗口时关键状态/停止动作不能消失。
检查键盘焦点、按钮语义、禁止项理由、错误文本和长路径换行。
不为了“设计统一”引入完整主题系统、新 Logo、动画库或第二套导航。

## 10. UI 验收

每一条可宣称的 GUI 功能要绑定真实版本、路径/页面名称、输入状态、执行动作、预期/实际结果、截图和后台/数据证据。
无设备 screenshot 只证明无设备页面。fixture 的截图永久标记 TEST_FIXTURE。
视觉测试优先使用已授权本地 Browser；Computer Use 用于操作系统或视觉特有问题。详见 [调试协议](operations/COMPUTER_USE_DEBUGGING.md)。
