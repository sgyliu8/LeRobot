# Hardware Setup

本项目面向一只 SO-101 leader、一只 SO-101 follower，以及 wrist/front 两路相机。
USB 枚举成功只说明设备被操作系统看见，不等于角色、供电、校准或运动条件已经成立。

## 设备身份

在 UI 中绑定前，先把操作系统中的设备与实物逐一对应：

| 角色 | 项目用途 | 必须确认的身份 |
|---|---|---|
| Leader | 操作者目标输入 | 实物标签、USB/串口实例、实际端口 |
| Follower | 执行目标 | 实物标签、USB/串口实例、实际端口 |
| Wrist camera | 近距离手眼视角 | 实际画面、USB 实例、后端参数 |
| Front camera | 桌面全局视角 | 实际画面、USB 实例、后端参数 |

普通 `COM1`、猜测的 camera index 或两个相似设备名称都不能作为默认绑定。拔插后端口或相机
index 可能变化，应重新核对身份而不是沿用旧数字。

## 相机键

现有数据约定保留以下键：

- `arm`：wrist camera；
- `table_veiw`：front camera。

`table_veiw` 的拼写是现有数据合同的一部分。在同一数据集内不得静默改成另一个名称。
浏览器 `deviceId`、Windows DirectShow 设备、OpenCV index 是不同标识，不能直接互换。

正式录制前记录每路相机的：

- 角色和实际画面；
- 后端与稳定设备标识；
- 实际宽、高和捕获率；
- 打开、释放与重新打开是否成功。

预览、诊断和 recorder 不能同时占用同一路相机。进入录制前先关闭其他预览程序并完成句柄交接。

## Motors、校准与遥操作

以下操作含义不同：

- **Setup motors**：可能写入 motor ID、baud 或其他总线设置；不是日常启动步骤。
- **Calibrate**：建立或更新关节标定；不能只因换了会话就强制重做。
- **Teleoperate**：连接两臂并向 follower 发送操作者目标；会产生真实运动。

若现有校准与同一台实物、同一配置匹配，先备份并复用。除非有明确故障证据和现场批准，
不要自动重写 motor ID、baud、firmware 或校准文件。

## 运动前检查

每次有限运动会话开始前，确认：

- leader、follower 与两路相机角色仍正确；
- 底座和桌面支架固定，工作区无人体、线缆和易碎物；
- 舵机供电符合实物电源标签；
- follower 从已知、低风险姿态开始；
- 操作者在现场并只移动 leader；
- UI 正常 Stop 与独立断电/停止方法都可用；
- 本次模式、动作范围和持续时间已经明确。

模式切换、异常、重连、校准改变或操作者离开后，需要重新确认这些条件。

## 有限遥操作

1. 先连接并观察状态，确认没有陈旧 telemetry。
2. 以小幅、慢速的 leader 运动验证方向与关节映射。
3. 出现反向、突跳、通信超时、异常声音或线缆拉扯时立即结束，并使用独立停止方式。
4. 超时后不要盲目重发同一动作；先确认机械臂实际状态。
5. 遥操作通过不等于录制、Replay 或策略推理已经安全。

关节目标限制与单位必须来自实际 profile。`max_relative_target` 只约束相邻位置目标差，
不代表速度、力、碰撞或工业功能安全保证。
